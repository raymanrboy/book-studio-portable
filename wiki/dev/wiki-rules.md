# Як вести цю вікі

> Вікі пише й підтримує агент; власник читає, дає джерела й напрям. Мета — щоб новий агент за кілька
> хвилин опинився в потрібному місці коду і знав, *чому* все так, а не інакше.
> Ідея — «LLM Wiki» (постійна база знань, яку агент нарощує, а не перечитує джерела щоразу).

## Три шари

1. **Джерела** — код (`app/`) як правда про те, *як* зараз працює програма, і матеріали власника
   в `wiki/raw/` (лише читаються, не змінюються).
2. **Вікі** — сторінки в `wiki/`. Пише лише агент.
3. **Схема** — `AGENTS.md` (+ `CLAUDE.md`) у корені: правила роботи і ця сторінка.

## Розкладка

| Папка / файл | Що там | `type` |
|---|---|---|
| `index.md` | каталог усіх сторінок | `index` |
| `log.md` | журнал змін вікі (лише дописується) | — |
| `overview.md`, `glossary.md`, `code-map.md` | вхідні сторінки | `overview`, `reference` |
| `security.md` | заборони | `rule` |
| `architecture/` | будова: запуск, сервер, інтерфейс, маршрути, дані | `architecture`, `reference` |
| `features/` | розділи програми | `feature` |
| `integrations/` | зовнішні сервіси | `integration` |
| `rules/` | правила предметної області | `rule` |
| `flows/` | покрокові шляхи | `flow` |
| `owner/` | як власник хоче працювати і бачити інтерфейс | `owner` |
| `decisions.md`, `recipes.md` | рішення з причинами; «як змінити X» | `decision`, `recipe` |
| `dev/` | встановлення, тести, перегляд, ця сторінка | `dev` |
| `plans/` | плани й відкриті питання | `plan` |
| `raw/` | джерела власника як є | — |

## Сторінка

```markdown
---
title: Назва українською
type: feature
updated: 2026-09-17
code:
  - app/studio/orders.py
---
# Назва

> Суть у 1–3 реченнях.

## …змістовні розділи…

## Де в коді
- [app/studio/orders.py](../../app/studio/orders.py) — `plan_for()`, `arrange_pages()`, `PRINTIFY_PAGES`

## Пов'язане
- [Інша сторінка](../rules/printer-rule.md)
```

- Одна сторінка — одна тема; коротко, без переказу коду.
- Імена файлів — латиницею через дефіс; заголовки — українською.
- Посилання — звичайні відносні Markdown-посилання; шлях із пробілами — у кутових дужках:
  `[x](<../app/Book Studio.pyw>)`.
- **Код — посилання на файл + назви функцій** (`name()`) і констант (`NAME`) *після* посилання на тому ж
  рядку. Номери рядків не писати.
- `code:` у шапці — файли, які сторінка **описує** (для карти «файл → сторінки»); тека з `/` у кінці
  покриває всі файли в ній.
- `updated:` — дата останньої змістовної зміни сторінки.
- Рішення записувати з датою й причиною в [decisions.md](../decisions.md): так ніхто не «виправить»
  свідомий вибір власника.
- Жодних ключів, токенів, паролів і справжніх даних покупців.

## Перевірка — `app/tools/wiki_check.py`

```
python app/tools/wiki_check.py            # усе гаразд → код 0
python app/tools/wiki_check.py --changed  # які сторінки описують змінені в git файли
python app/tools/wiki_check.py --map      # файл коду → сторінки
```
Перевіряє: шапки, живі посилання, що згадані `функції()` і `КОНСТАНТИ` існують у файлі, що кожна
сторінка є в `index.md`, що кожен файл коду описаний хоча б однією сторінкою, що таблиця
[маршрутів](../architecture/api-routes.md) збігається з кодом, формат `log.md`, і **числа, які вікі
називає словами** (`stale_numbers()`, з 22.09.2026): скільки тестів у `dev/testing.md` і скільки
маршрутів в `index.md`, `architecture/api-routes.md`, `architecture/server.md` (`NUMBER_CLAIMS`). Останнє —
бо перевірка проходила, поки у вікі стояло 117 тестів проти 182 і 88 маршрутів проти 92 (знайшов
аудит): структуру вона звіряла, а числа в тексті — ні. З 23.09.2026 звіряється **кожна** згадка на цих
сторінках (а не лише перша), тести рахуються як їх бачить запуск (`ast`: методи `test_…` класів), а
«N … проти M» — історія, її не чіпають.
Та сама перевірка — тест `test_wiki.py`, тож розходження вікі з кодом валить тести.

## Операції

- **Після кожної задачі в коді** (обов'язково):
  1. `wiki_check.py --changed` → оновити перелічені сторінки (зміст, «Де в коді», `updated`);
  2. нове рішення → [decisions.md](../decisions.md); нове слово власника → [glossary.md](../glossary.md);
     новий маршрут → [api-routes.md](../architecture/api-routes.md); новий файл → [code-map.md](../code-map.md)
     і `code:` потрібної сторінки;
  3. запис у `log.md`;
  4. `wiki_check.py` і тести — без помилок.
- **Додавання джерела** (власник дав текст, скриншот, документ): покласти в `raw/` (якщо це файл),
  прочитати, обговорити головне з власником, рознести по сторінках (часто 5–15 сторінок), оновити
  `index.md`, запис `ingest` у `log.md`.
- **Питання**: спершу `index.md` → сторінки → код. Цінну відповідь (порівняння, аналіз) — зберегти
  новою сторінкою.
- **Огляд (lint)** на прохання або час від часу: суперечності між сторінками, застарілі твердження,
  сторінки без вхідних посилань, поняття без своєї сторінки, прогалини; запис `lint` у `log.md`.

## Журнал

Заголовок запису: `## [РРРР-ММ-ДД] вид | що сталося`, вид — `setup`, `ingest`, `update`, `query`,
`lint`, `decision`. Нові записи — вгорі. Останні записи: `grep "^## \[" wiki/log.md | head -5`.
